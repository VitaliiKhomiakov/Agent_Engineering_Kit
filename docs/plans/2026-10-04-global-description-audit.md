### Observations requiring attention

**R1 — Entry templates are heavier than the stated brevity goal (low; improvement).**

[Root AGENTS template](../../templates/AGENTS.root.md#engineering-and-evidence)
has 112 physical / 99 nonblank lines;
[policy entry](../../templates/policy-entry.md#scope-permissions-and-evidence)
has 96 / 81. The defaults give a soft substantive-line range of 40–70. Raw
nonblank counts are a screening measure, not an exact implementation of the
undefined “substantive” metric, a hard violation or a token measurement.
Both entries repeat substantial check timing, repetition, baseline and model
procedure text while also routing to its owners. A target's real project map
will add content. This weakens the claim that the starting entries are short
and increases the chance of future drift between summaries and owners.

Recommended bounded change: shorten procedural summaries and retain clear routes
to verification/model/work-mode owners, preserving the explicitly required
always-loaded language, scope and permission constraints. Do not mechanically
truncate instructions or weaken required checks to hit a number. Detailed
technology entries are generally modest (24–78 physical lines); the separate
Next.js structure topic has 102 and is conditional. No global documentation
split or deletion of historical evidence is justified by this observation.

**R2 — Next.js public cross-feature dependency policy can be clearer (low; ambiguity).**

In [dependency rules](../../standards/nextjs-feature-structure.md#compact-product-capability-structure),
the first sentence restricts a feature to its own code plus public contracts from
entities/shared. The following sentences prohibit other features' internals and
offer an explicit contract as an alternative to composition above features.
It is not completely explicit whether importing another feature's public entry
is an allowed exception, or whether a consumer-owned contract must be injected
from above. For example, agents could disagree about a `place-order` feature
importing a public `cart` operation even without a cycle or private import.

This is an interpretive gap, not a demonstrated invalid application or a Next.js
API defect. Clarify the intended dependency direction and give one allowed and
one forbidden import example in this existing owner. Keep the compact capability
architecture; no FSD migration or extra layer follows from the finding.
